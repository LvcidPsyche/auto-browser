# Release 1.12.2

A controller patch release over 1.12.1: the #244 fix (#246), provider API keys with surrounding whitespace (#248),
and four Dependabot bumps (#239, #234, #236, #235). The three PyPI packages change only in version. Tagging is the
maintainer's step (below).

## Checks run before merging (2026-11-02)

**Live `tool_choice` probe** (`scripts/probe_tool_choice.py`, kept on the carrier branch `claude/probe-tool-choice`):
OpenRouter, the controller's real request without its image, named choice then unforced, per model.

| Model | Named `tool_choice` | Unforced | Verdict |
|---|---|---|---|
| anthropic/claude-opus-5.5 | 400, matcher fires | 200, tool call | fixed by #246 |
| anthropic/claude-sonnet-5.5 | 400, matcher fires | 200, tool call | fixed by #246 |
| anthropic/claude-fable-5.1 | 400, matcher fires | 200, tool call | fixed by #246 |
| anthropic/claude-haiku-5.5 | 200, tool call | 200, tool call | named accepted |
| deepseek/deepseek-v4-pro | 200, tool call | 200, tool call | named accepted |
| deepseek/deepseek-v4-flash | 200, tool call | 200, tool call | named accepted |
| deepseek/deepseek-chat | 200, tool call | 200, tool call | named accepted |

- The three Claude 400s carry only "Provider returned error" in `error.message`; the text naming `tool_choice`
  ("tool_choice: type \"tool\" and \"any\" are not supported for this model.") is only in `error.metadata.raw`. A
  message-only matcher would have missed all three.
- OpenRouter served the DeepSeek models from Crusoe and DigitalOcean with no reasoning tokens. DeepSeek's own API
  with thinking on (the CHANGELOG's DeepSeek case) was not checked live: no DeepSeek key.
- Mythos 5.1 is not listed on OpenRouter, so it was dropped from the CHANGELOG's OpenRouter list.

**Live run through the real adapter** (`ProviderRegistry`, real httpx, 1280x800 screenshots, OpenRouter):
Opus 5.5 over three steps sent named → 400 → unforced → 200 on step 1, then one unforced request on steps 2 and 3,
with `(base_url, model)` remembered; Haiku 5.5 kept the named choice on both steps. The same run found the key
whitespace bug fixed in #248 (401 "Missing Authentication header" on a key with a leading space).

**Release audit** (`scripts/release_audit.py --skip-doctor`, Python 3.13 venv): launch files, advisory triage,
ruff, version/Playwright/bridge parity, agent and fixture evals, pip-audit, npm audit, and the wheel builds passed;
controller tests 4,091 passed with 93.04% coverage and 1 failure,
`test_request_gate_attach_chromium.py::test_chrome_fails_the_operators_cross_origin_post_redirect_while_the_gate_is_attached`,
which fails the same way on v1.12.1 in this sandbox (its Chromium is newer than Playwright's pin) and passes in CI's
`host-tests (3.11)`. Compile checks and the secret scan, which the audit stops before, were run by hand: both clean.

**Independent review of the notes**: no blockers. Applied: Mythos 5.1 dropped, the DeepSeek case attributed to
DeepSeek's documentation, "logs once" and "one extra request" qualified for concurrent first requests, FastAPI's
range spelled out, the GHSA described, Fable 5.1 added to `docs/llm-adapters.md`, and this plan moved to `done/`.

OpenRouter spend for all of the above: $0.20.

## Tag (maintainer)

After the push-to-main `ci.yml` run on the merged release commit is green (release.yml and docker-publish.yml refuse
a tag without it), from the repo root on an up-to-date main:

```
git tag -a v1.12.2 -m "v1.12.2" && git push origin v1.12.2
```

That publishes the three PyPI packages and the `1.12.2`, `1.12` and `latest` images; PyPI versions cannot be reused.
If the tag lands on a later day, change the CHANGELOG date first.
